Auditoria Individual

A auditoria individual permite analisar qualquer site sob múltiplas perspectivas, gerando insights detalhados sobre performance, UX, SEO e comportamento do usuário em tempo real.

Como Realizar uma Auditoria

1. Acesso ao Painel

Navegue até o menu lateral e clique em "Nova Análise". A interface apresentará uma search bar centralizada para inserção da URL.

2. Inserção da URL

Digite a URL completa do site alvo. É obrigatório incluir o protocolo https:// ou http:// para garantir análise correta.

Exemplos de URLs válidas:

https://exemplo.com.br
https://www.exemplo.com.br/pagina

3. Seleção de Agents (Modo Manual)

Ao selecionar o modo manual, escolha 1 persona criada na sua conta. Sem personas salvas, o modo manual permanece indisponível.

4. Execução da Análise

Clique no botão "ANALISAR" para iniciar o processo. A IA examinará o site sob múltiplas dimensões, gerando insights acionáveis em poucos segundos.

Métricas Analisadas

Performance

Tempo de carregamento, otimização de recursos, Core Web Vitals (LCP, FID, CLS), compressão de assets, cache HTTP/HTTPS, tamanho total da página, número de requisições.

UX/UI

Usabilidade, acessibilidade WCAG, design responsivo, navegação intuitiva, hierarquia visual, contraste de cores, tamanho de fontes, espaçamento, feedback de interações.

SEO

Meta tags (title, description, keywords), estrutura HTML semântica, headings H1-H6, sitemap.xml, robots.txt, canonical tags, Open Graph, Twitter Cards, schema.org structured data.

Comportamental

Jornada do usuário, pontos de fricção, taxa de rejeição, tempo na página, taxa de conversão, funil de conversão, heatmap de cliques, scroll depth, comportamento em dispositivos móveis.

Considerações Importantes

Sites Protegidos

Sites com autenticação, behind VPN ou com proteções anti-bot podem não ser analisados completamente. Considere usar URLs públicas ou ambientes de staging.

Single Page Applications (SPAs)

SPAs baseadas em JavaScript (React, Vue, Angular) são analisadas considerando o estado inicial renderizado no servidor (SSR) ou o conteúdo estático disponível.

Frequência de Análise

Recomenda-se analisar o site periodicamente (semanal ou mensal) para acompanhar evoluções e identificar regressões após atualizações.

Interpretação dos Resultados

Score Global (0-100)

Pontuação agregada calculada com base em todas as métricas analisadas. Scores acima de 70 indicam boa qualidade geral, acima de 85 indicam excelência.

Priorização de Correções

As recomendações são ordenadas por impacto estimado na experiência do usuário e facilidade de implementação. Foque primeiro em itens de alto impacto e baixa complexidade.

Contexto de Negócio

Considere o objetivo do site ao priorizar correções. E-commerce deve focar em checkout e performance, blog em SEO e legibilidade, landing page em conversão.

Sites locais

Como auditar um site localhost com Ngrok

Use este guia quando o seu projeto ainda está rodando apenas no seu computador, como em localhost:3000. O Ngrok cria uma URL pública temporária para que a SSW Intelligence consiga acessar e analisar o site.

Por que precisa?

A auditoria roda fora do seu computador. Por isso, ela precisa de um link HTTPS acessível pela internet, não apenas uma URL local.

Quanto tempo leva?

Depois da primeira configuração, o processo normalmente leva menos de 1 minuto: abrir o terminal, rodar o comando e copiar o link.

Atenção de segurança

O link fica público enquanto o tunnel estiver ativo. Não exponha painéis administrativos, dados reais ou ambientes com segredos sensíveis.

Antes de começar

Seu projeto precisa estar rodando

Abra o site no navegador e confirme a porta local. Exemplos comuns:

http://localhost:3000 http://localhost:5173 http://localhost:8000

Você precisa de uma conta Ngrok

Crie uma conta gratuita em ngrok.com, baixe o agent para seu sistema operacional e copie o authtoken no dashboard.

Passo a passo completo

1

Instale o Ngrok

Acesse o dashboard do Ngrok, escolha seu sistema operacional e siga a instalação indicada. No Windows, normalmente basta extrair o executável e abrir o terminal na pasta onde ele está.

2

Conecte sua conta ao agent

Copie seu authtoken no dashboard do Ngrok e rode o comando abaixo uma única vez:

ngrok config add-authtoken SEU_TOKEN_AQUI

Não compartilhe esse token. Ele identifica sua conta no Ngrok.

3

Descubra a porta do seu projeto

A porta é o número depois de localhost:. Se o site abre em http://localhost:3000, a porta é 3000.

Next.js / React3000
Vite5173
FastAPI / Django8000
4

Abra o tunnel para a porta correta

Com o site local aberto, rode o comando usando a porta do seu projeto:

ngrok http 3000

Se o seu projeto usa Vite, por exemplo, troque para ngrok http 5173.

5

Copie a URL HTTPS gerada

No terminal, procure a linha Forwarding. Copie o endereço que começa com https://.

https://abc1234.ngrok-free.app
6

Cole a URL na SSW Intelligence

Volte para a tela de análise, cole a URL pública gerada pelo Ngrok e clique em Analisar. Mantenha o terminal do Ngrok aberto até a análise terminar.

Checklist antes de analisar

  • O site local abre normalmente no seu navegador.
  • O comando do Ngrok aponta para a mesma porta do projeto.
  • Você copiou o link HTTPS, não o link HTTP.
  • O terminal do Ngrok continua aberto durante a auditoria.

Problemas comuns

A URL do Ngrok abriu, mas a SSW não consegue analisar

Abra o link do Ngrok em uma aba anônima. Se pedir login, bloquear host, mostrar erro de CORS ou carregar uma tela vazia, corrija isso no seu projeto antes de iniciar a auditoria.

Meu app Vite mostra erro de host não permitido

Configure seu servidor local para aceitar o domínio gerado pelo Ngrok ou rode o dev server expondo host local. Em alguns projetos, isso exige ajustar allowedHosts ou a configuração equivalente do framework.

O link mudou depois que fechei o terminal

No plano gratuito, a URL temporária pode mudar a cada nova sessão. Sempre copie a URL atual exibida na linha Forwarding.

Quero parar de expor meu site local

Volte ao terminal onde o Ngrok está rodando e pressione Ctrl + C. O link público deixa de encaminhar tráfego para o seu computador.

Boas práticas

Use o Ngrok apenas pelo tempo necessário para auditar. Evite expor rotas administrativas, dashboards internos, bancos locais, endpoints com chaves privadas ou ambientes com dados reais de clientes.

Sites com anti-bot

Como liberar a auditoria da S.S.W

Use este guia quando a captura for bloqueada por Cloudflare, firewall, WAF, captcha ou plugin de segurança. A ideia é simples: a S.S.W envia dois sinais privados e o responsável pelo site permite esses sinais.

1. Adicione o domínio

Informe apenas o domínio principal, como exemplo.com.br. A plataforma gera um código privado para aquele site.

2. Copie a instrução

Envie a mensagem pronta para quem cuida do Cloudflare, firewall, WAF ou plugin de segurança. O usuário não precisa entender a parte técnica.

3. Teste novamente

Depois que a regra for aplicada, rode a auditoria de novo. Se o site ainda bloquear, continue sem captura visual ou revise a regra criada.

Mensagem que será enviada ao técnico

“Preciso liberar a auditoria da S.S.W Intelligence. Permita requisições com User-Agent contendo SSW-Intelligence-Auditor e com o header X-SSW-Audit-Token igual ao código gerado pela plataforma. Essa regra deve pular desafios de bot/captcha apenas quando os dois sinais existirem ao mesmo tempo.”

Regra de segurança

Não libere qualquer robô. A liberação deve depender dos dois sinais juntos: User-Agent oficial + header privado. Se o código vazar, gere um novo código na tela de liberação.

Sites com anti-bot

Como liberar uma auditoria com domínio autorizado

Use este guia quando a própria análise indicar bloqueio por Cloudflare, WAF, captcha, firewall ou proteção anti-bot. A liberação serve para identificar a SSW como auditoria autorizada sem abrir o site para qualquer automação.

Primeiro tente normal

Se a análise terminar normalmente, nada precisa ser configurado. Esta etapa só entra quando o acesso for recusado.

Comprove propriedade

A plataforma gera um token para provar que você controla o domínio antes de permitir qualquer tentativa autorizada.

Header secreto

O firewall reconhece a auditoria por uma combinação de header privado e User-Agent oficial, sem depender de IP fixo.

Antes de começar

Tenha acesso a pelo menos um dos pontos abaixo. Eles serão usados para publicar o token de verificação e liberar a auditoria no mecanismo de segurança do site.

  • Acesso ao DNS do domínio para criar um registro TXT.
  • Acesso ao servidor para publicar um arquivo em /.well-known/.
  • Acesso ao HTML para inserir uma meta tag temporária.
  • Acesso ao Cloudflare, WAF ou firewall para criar a regra de permissão.

Configuração em etapas

1

Cadastre o domínio principal

Abra Autoridade Digital > Domínios Autorizados e informe apenas o domínio raiz, sem protocolo, caminho ou parâmetros. A liberação vale para o domínio e seus subdomínios quando a API reconhecer a mesma base.

correto: exemplo.com.br evite: https://exemplo.com.br/pagina?utm=...
2

Escolha como publicar o token

Depois de salvar, a plataforma mostra três alternativas. Use a que for mais simples para sua equipe técnica:

DNS TXTIdeal quando você gerencia o domínio no Registro.br, Cloudflare, Hostinger ou provedor similar.
Arquivo públicoIdeal quando você consegue subir arquivos no servidor ou deploy do site.
Meta tagIdeal quando você consegue editar o HTML da página inicial.
3

Publique exatamente o valor exibido

Copie o token sem alterar letras, espaços ou quebras. Para DNS, use o nome e o valor mostrados na plataforma. Para arquivo, o conteúdo do arquivo deve ser somente o token. Para meta tag, cole a tag dentro do <head>.

DNS TXT_ssw-verify
Arquivo/.well-known/
Meta tagssw-verification
4

Valide dentro da SSW

Volte para a tela de domínios e clique em Verificar. DNS pode levar alguns minutos para propagar. Se falhar, aguarde, confirme se o token está público e tente novamente. Quando aprovado, o domínio muda para o status Verificado.

5

Crie a regra de permissão no anti-bot

No Cloudflare, WAF ou firewall, permita a requisição somente quando os dois sinais existirem ao mesmo tempo: header secreto correto e User-Agent oficial. Evite liberar por IP, porque serviços de nuvem podem trocar o endereço de saída.

X-SSW-Audit-Token: token_do_domínio User-Agent contém: SSW-Intelligence-Auditor/1.0
6

Faça um novo teste e ajuste se necessário

Rode a auditoria na mesma URL. Se continuar bloqueando, revise se o domínio cadastrado é o mesmo da URL final, se a regra do firewall está ativa antes do desafio anti-bot e se o token usado na regra é o token de auditoria, não o token de verificação.

O que deve ser feito caso o site não seja seu

Peça autorização ao responsável técnico do site. Ele não precisa fornecer senhas, painel administrativo ou acesso interno; precisa apenas publicar o token de verificação e criar a regra de permissão no anti-bot.

Responsável pelo site

Publica o token por DNS, arquivo ou meta tag e configura a regra no firewall/WAF.

Você na SSW

Cadastra o domínio, copia os tokens exibidos e clica em verificar depois que o responsável confirmar a publicação.

Mensagem sugerida para enviar:

"Precisamos liberar a auditoria legítima da SSW Intelligence. Por favor, permita requisições que tenham o header X-SSW-Audit-Token com o token informado na plataforma e User-Agent contendo SSW-Intelligence-Auditor/1.0. Essa liberação deve valer apenas para o domínio validado."

Segurança da liberação

Não crie uma regra ampla para liberar qualquer bot. A liberação deve depender do header secreto e do User-Agent oficial. Se suspeitar de exposição do token, use a opção de rotacionar token na tela de domínios autorizados.

Análise Comparativa

Compare dois sites simultaneamente e descubra quem leva a vantagem competitiva. Análise lado a lado com métricas detalhadas e recomendações estratégicas.

Como Realizar uma Comparação

1. Acesso ao Modo Comparativo

No menu lateral, clique em "Nova Análise" e selecione a aba "Modo Comparativo" para comparar dois sites simultaneamente.

2. Configuração das URLs

Digite a URL do seu site no campo "Site A" e a URL do concorrente no campo "Site B". Use URLs completas com protocolo.

Exemplo de configuração:

Site A: https://seusite.com.br
Site B: https://concorrente.com.br

3. Execução da Comparação

Clique em "COMPARAR" para iniciar a análise. O sistema analisará ambos os sites sob as mesmas condições e métricas.

Interpretação de Resultados

Vencedor Global

Site com maior score agregado em todas as categorias analisadas. O vencedor é determinado pela média ponderada de performance, UX, SEO e comportamento.

Pontos de Melhoria

Áreas onde seu site perdeu para o concorrente com recomendações específicas para alcançar ou superar o desempenho do adversário.

Vantagens Competitivas

Pontos fortes do seu site em relação ao concorrente. Identifique onde você já lidera e mantenha essas vantagens.

Oportunidades

Gaps identificados que podem ser explorados para ganhar vantagem competitiva. Áreas onde pequenas melhorias podem gerar grandes ganhos.

Estratégias de Benchmarking

Seleção de Concorrentes

Escolha concorrentes diretos (mesmo nicho), concorrentes indiretos (mesmo público-alvo) e referências do setor (líderes de mercado) para uma visão completa do cenário competitivo.

Análise de Páginas Específicas

Compare páginas equivalentes (home vs home, checkout vs checkout, blog vs blog) para insights mais relevantes e acionáveis.

Monitoramento Contínuo

Realize comparações periódicas para acompanhar evoluções do mercado e identificar quando concorrentes implementam melhorias significativas.

Limitações e Considerações

Paridade de Condições

A análise é realizada sob as mesmas condições para ambos os sites, mas diferenças de infraestrutura, CDN ou geolocalização podem afetar resultados de performance.

Conteúdo Dinâmico

Sites com conteúdo personalizado ou A/B testing podem apresentar variações. A análise considera o conteúdo padrão apresentado.

Contexto de Negócio

Métricas técnicas não refletem necessariamente a estratégia de negócio. Considere o posicionamento, público-alvo e objetivos ao interpretar resultados.

Gestão de Agents

Crie e gerencie agents personalizados para análises mais precisas. Cada agent representa um perfil de usuário com características específicas, permitindo análises sob diferentes perspectivas.

Como Gerenciar Agents

1. Acesso ao Painel de Agents

No menu lateral, clique em "Agents" para acessar o painel de gestão de perfis de usuários.

2. Criação de Nova Agent

Clique em "Criar Agent" e preencha os campos obrigatórios: nome, idade, profissão, objetivos e características comportamentais.

Campos obrigatórios:

  • ⬢ Nome: Identificação da agent
  • ⬢ Idade: Faixa etária do perfil
  • ⬢ Profissão: Ocupação principal
  • ⬢ Objetivos: Metas e necessidades
  • ⬢ Características: Comportamentos e preferências

3. Salvamento e Utilização

Após preencher os dados, clique em "Salvar". A agent ficará disponível para seleção em análises individuais e comparativas.

Melhores Práticas

Baseado em Dados Reais

Crie agents baseadas em dados reais do seu público-alvo: analytics, pesquisas, feedback de clientes e entrevistas. Evite suposições.

Combine Perspectivas

Crie agents diferentes para obter visões complementares ao longo de análises separadas. Cada análise manual usa uma persona principal para manter o diagnóstico focado.

Atualização Periódica

Revise e atualize agents periodicamente conforme evolução do produto, mudanças no mercado e feedback contínuo dos usuários.

Específicas por Contexto

Use agents específicas para cada tipo de análise: landing page (foco em conversão), checkout (foco em usabilidade), blog (foco em conteúdo).

Limites e Recomendações

Máximo de três Agents por Análise

O sistema permite selecionar 1 agent por análise manual para manter o relatório focado e acionável. Use análises separadas para comparar perspectivas.

Consistência entre Análises

Use as mesmas agents em análises periódicas para garantir comparabilidade dos resultados ao longo do tempo.

Agent vs Público-Alvo

Agent é um perfil específico, público-alvo é um segmento mais amplo. Crie múltiplas agents para representar diferentes segmentos do seu público.

Relatórios e Insights

Analise relatórios detalhados e extraia insights acionáveis para melhorar seu site. Exporte dados em PDF e compartilhe com sua equipe para tomada de decisões baseada em dados.

Estrutura do Relatório

Score Global

Pontuação agregada (0-100) representando a qualidade geral do site. Calculada com base em todas as métricas analisadas, ponderadas por impacto na experiência do usuário.

Métricas por Categoria

Scores detalhados para Performance, UX/UI, SEO e Comportamental. Cada categoria possui submétricas específicas com pontuação individual.

Análise Comportamental

Insights sobre jornada do usuário, pontos de fricção e oportunidades de conversão baseados nas agents selecionadas. Inclui mapa de jornada e identificação de gargalos.

Recomendações

Lista priorizada de ações para melhoria, com impacto estimado, complexidade de implementação e exemplos práticos de como aplicar cada recomendação.

Interpretação de Scores

90-100: Excelente

Site otimizado com poucas oportunidades de melhoria. Mantenha monitoramento contínuo para evitar regressões.

70-89: Bom

Site com qualidade satisfatória mas com oportunidades claras de melhoria. Foque em itens de alto impacto para atingir excelência.

50-69: Regular

Site com problemas significativos que afetam experiência. Priorize correções críticas antes de investir em melhorias incrementais.

0-49: Crítico

Site com problemas graves que impedem uso efetivo. Requer intervenção imediata e plano de reestruturação completo.

Exportação e Compartilhamento

Exportação em PDF

Clique em "BAIXAR RELATÓRIO PDF" para gerar uma versão imprimível do relatório. O PDF inclui todas as métricas, recomendações e análise comportamental em formato profissional.

Compartilhamento com Equipe

Use o PDF para compartilhar resultados com stakeholders, desenvolvedores, designers e equipe de marketing. Facilita discussões e alinhamento sobre prioridades.

Histórico de Análises

O sistema mantém histórico de análises para acompanhamento de evolução. Compare relatórios ao longo do tempo para medir impacto das correções implementadas.

Uso Estratégico dos Relatórios

Planejamento de Roadmap

Use as recomendações priorizadas para planejar roadmap de melhorias. Combine impacto estimado com capacidade da equipe para definir cronograma realista.

Justificativa de Investimento

Relatórios quantificam problemas e oportunidades, facilitando justificativa de orçamento para correções técnicas e melhorias de UX.

Benchmarking Interno

Compare relatórios de diferentes páginas do mesmo site para identificar inconsistências e padrões que podem ser padronizados.

Aprendizado Contínuo

Revise relatórios periodicamente para identificar padrões recorrentes e oportunidades de melhoria sistêmicas no processo de desenvolvimento.

Nossa plataforma audita performance, SEO, clareza e usabilidade com apoio de IA; a S.S.W - Silva Serviços Web usa essa inteligência para criar sites, landing pages e sistemas web que já nascem orientados por dados.

Para garantir a confiabilidade dos dados, nossa infraestrutura não se baseia em suposições visuais. O sistema realiza uma captura real da estrutura da página, cruzando dados de código com métricas de performance vitais (Core Web Vitals) extraídas diretamente de fontes oficiais de medição. No entanto, dados técnicos isolados não contam a história completa de um site. A verdadeira inteligência da plataforma está na sua camada de processamento por Inteligência Artificial. Nós aplicamos perfis comportamentais simulados - os nossos arquétipos de "agents" - sobre as métricas extraídas. Isso significa que o sistema não apenas aponta uma falha técnica, mas contextualiza como esse erro impacta especificamente a jornada, a confiança e a retenção de um usuário dentro daquele nicho de mercado.

O resultado desse cruzamento de dados é um caminho claro: diagnosticar, priorizar e executar. Para quem já tem equipe, entregamos inteligência acionável. Para quem precisa de uma solução pronta, desenvolvemos a estrutura em código com foco em velocidade, confiança, conversão e crescimento.
